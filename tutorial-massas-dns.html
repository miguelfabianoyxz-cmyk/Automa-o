Como usar a ferramenta
Massas & DNS

Cole dados de teste (CPF, Nome, Conta…) e URLs de ambiente (HML, PROD, DEV…), escolha um engine de parse e gere tabelas interativas com produto cartesiano automático. Tudo roda no browser, sem servidor.

12 engines de parse Filtro em tempo real Export CSV · TSV · JSON 100% offline
1

Visão geralO que a ferramenta faz e como está organizada

A ferramenta recebe dois inputs — Massa de Dados (registros CSV/Excel) e DNS / Ambientes (lista de URLs) — e gera automaticamente três saídas:

Aba Massas
Tabela com todos os registros parseados da entrada CSV, com cabeçalho detectado automaticamente.
Aba DNS
Tabela com ambiente (badge colorido) e URL de cada linha do campo DNS, com inferência automática de ambiente.
Visão Combinada
Produto cartesiano: cada registro de massa combinado com cada URL. Ideal para testar todos os cenários de uma vez.
Stats Bar
Contadores em tempo real: total de registros, DNS, combinações, ambientes únicos e engine ativo.
2

Filtro em tempo real

1

Engine de ParseEscolha o motor que interpreta seus dados

Clique no painel "Engine de Parse" no topo da ferramenta para expandi-lo. Você verá um grid com 12 engines disponíveis. Clique em qualquer um para selecioná-lo.

ℹ️
Todos os engines rodam no browser. Não há chamada a servidor. Cada engine apenas altera as regras de parse: separador de coluna, headers conhecidos, inferência de ambiente e comportamentos especiais.
1
Abra o painel

Clique na barra "Engine de Parse" — ela se expande mostrando o grid de 12 linguagens.

2
Selecione o engine

Clique no card da linguagem desejada. O badge no topo ("🟨 JavaScript") se atualiza imediatamente. A barra abaixo do painel mostra as regras do engine ativo.

3
Leia as regras

A "parser strip" abaixo do painel descreve como aquele engine detecta separador, headers e ambientes. Use isso para formatar seus dados corretamente.

💡
Dica: se o seu time usa Python, selecione o engine Python para que as regras de parse sejam idênticas ao que o backend Flask faria. Isso garante consistência no teste.
2

Massa de DadosComo formatar e inserir seus registros de teste

Cole seus dados no campo esquerdo. O engine detecta automaticamente o separador e o cabeçalho.

Formatos aceitos:

CSV — vírgula
CPF,Nome,Conta,Agência
123.456.789-00,João Silva,12345-6,0032
987.654.321-00,Maria Souza,98765-4,0001
CSV — ponto-e-vírgula (padrão Excel BR)
CPF;Nome;Conta;Agência
123.456.789-00;João Silva;12345-6;0032
987.654.321-00;Maria Souza;98765-4;0001
TSV — tab (colado direto do Excel)
CPF	Nome	Conta	Agência
123.456.789-00	João Silva	12345-6	0032
Sem cabeçalho — colunas inferidas automaticamente
123.456.789-00,João Silva,12345-6,0032
987.654.321-00,Maria Souza,98765-4,0001
🔖
Detecção de cabeçalho: se a primeira linha contiver palavras como cpf, nome, conta, agência, email, telefone etc., ela é tratada como cabeçalho. Caso contrário, colunas padrão são atribuídas (CPF, Nome, Conta, Agência — ou Col1, Col2… no engine Go).
💡
Drag & Drop: arraste um arquivo .csv ou .txt diretamente sobre o card "Massa de Dados" para carregá-lo automaticamente.
3

DNS / AmbientesComo informar URLs e ambientes de teste

Cole as URLs no campo direito. Cada linha é uma entrada. Você pode prefixar com o nome do ambiente ou deixar o engine inferir pelo nome da URL.

Formato padrão — prefixo + espaço + URL
HML   app.hml.banco.com.br
PROD  app.prod.banco.com.br
DEV   api.dev.banco.com.br
SIT   api.sit.banco.com.br
UAT   api.uat.banco.com.br
Sem prefixo — ambiente inferido pelo nome da URL
app.hml.banco.com.br
app.prod.banco.com.br
api.dev.banco.com.br
Engine Rust — separador pipe ou ponto-e-vírgula
HML|app.hml.banco.com.br
PROD|app.prod.banco.com.br
DEV;api.dev.banco.com.br
Engine Kotlin — URL primeiro, ambiente no final
app.hml.banco.com.br HML
app.prod.banco.com.br PROD
⚠️
Engine TypeScript/Deno: linhas iniciadas com # ou // são tratadas como comentários e ignoradas. O ambiente HOM é usado no lugar de HML.
4

Gerar TabelasComo acionar o parse e interpretar os resultados

Com os dados preenchidos, clique em "Gerar Tabelas" (ou pressione ⌘ Enter). Uma barra de estatísticas aparecerá seguida de três abas.

1
Clique em "Gerar Tabelas"

O engine selecionado processa os dois campos e monta as três saídas. Uma notificação toast confirma qual engine foi usado.

2
Verifique a Stats Bar

Mostra: nº de registros, nº de DNS, nº de combinações (massa × DNS), ambientes únicos e engine ativo.

3
Navegue pelas abas

Use as abas Massas, DNS / Ambientes e Visão Combinada para explorar cada saída.

4
Use "Limpar" para recomeçar

O botão "Limpar" (vermelho) apaga os dois campos de entrada, os filtros e os resultados, voltando ao estado inicial.

5

Filtrar e OrdenarBusca instantânea e ordenação por qualquer coluna

Cada aba possui um campo de busca independente. A filtragem é aplicada em todas as colunas simultaneamente, com debounce de 160 ms.

1
Filtrar por texto

Digite qualquer valor no campo "Filtrar…" — CPF, nome, URL, ambiente. Os termos encontrados ficam destacados em laranja. O contador "X de Y" mostra quantos resultados batem.

2
Ordenar por coluna

Clique no cabeçalho de qualquer coluna para ordenar. Clique de novo para inverter (ASC → DESC). O ícone ↕ vira ↑ ou ↓ e fica laranja na coluna ativa.

3
Navegação por páginas

Resultados são paginados em grupos de 25. Use os botões ‹ › ou os números de página abaixo de cada tabela para navegar.

💡
Use ⌘ K para focar instantaneamente no campo de busca da aba Massas sem precisar clicar.

Badges de AmbienteReferência de cores e palavras-chave reconhecidas

O engine detecta o ambiente pelo prefixo explícito (ex: HML url) ou infere pelo nome da URL. As palavras-chave abaixo são reconhecidas automaticamente:

BadgePalavras-chave reconhecidasExemplos de URL
HML hml, homolog app.hml.banco.com.br
PROD prod, prd app.prod.banco.com.br
DEV dev api.dev.banco.com.br
SIT sit api.sit.banco.com.br
UAT uat api.uat.banco.com.br
QAS qas, qa api.qas.banco.com.br
— Nenhuma correspondência URL sem palavras-chave conhecidas
🔖
Engines especiais: Swift usa PRD (não PROD) como fallback padrão. TypeScript/Deno usa HOM para homologação. Kotlin detecta também STG (staging). Java prioriza PROD antes de HML na inferência.
9

Os 12 EnginesDiferenças e comportamentos específicos de cada linguagem

Cada engine replica as convenções da linguagem correspondente. As diferenças principais estão listadas abaixo:

JS
🟨 JavaScript
Node.js · Express
Engine padrão. Separador: tab > ; > ,. Produto cartesiano com for…of.
PY
🐍 Python
Flask 3 · Gunicorn
Usa str.strip() e str.lower(). Produto com itertools.product.
JAVA
☕ Java
Spring Boot 3.2
Prioridade invertida: infere PROD antes de HML. Headers em HashSet.
GO
🐹 Go
net/http · stdlib
Sem cabeçalho → colunas Col1, Col2…ColN (não CPF/Nome).
PHP
🐘 PHP
Built-in server
Usa str_contains() PHP 8. Sem dependências externas.
RB
💎 Ruby
Sinatra 3
Separador com indexOf. Produto com blocos .each { |r| }.
RS
🦀 Rust
Actix-web 4
DNS aceita ENV|URL e ENV;URL além do espaço padrão.
C#
🔷 C#
.NET 8 Minimal API
Headers em HashSet<string>. Usa IsNullOrWhiteSpace().
KT
🎯 Kotlin
Ktor 2.3
DNS aceita formato url ENV (env no final). Detecta STG.
SW
🦅 Swift
Vapor 4
Separador pelo mais frequente (contagem). Fallback padrão: PRD.
TS
🦕 TypeScript
Deno · Oak 12
Detecta | como separador. Usa HOM. Ignora comentários # //.
R
📊 R
Plumber 1.2
Loop aninhado para produto (sem expand.grid). Usa trimws().

11

Drag & DropCarregue arquivos arrastando diretamente para os campos

Em vez de copiar e colar, você pode arrastar arquivos direto para os cards de entrada.

1
Arraste o arquivo

Arraste um arquivo .csv ou .txt da sua área de trabalho para cima do card "Massa de Dados" ou "DNS / Ambientes".

2
Solte sobre o card

O card ficará destacado com borda laranja enquanto você segura o arquivo. Ao soltar, o conteúdo é carregado automaticamente e o contador de linhas se atualiza.

3
Gere normalmente

Com o arquivo carregado, clique em "Gerar Tabelas" ou pressione ⌘ Enter.

💡
Encoding: o arquivo é lido como UTF-8. Certifique-se de que seu CSV está salvo nesse encoding para evitar problemas com acentos (ã, ç, é…).
