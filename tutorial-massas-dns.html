Visão geralO que é, por que existe e como funciona por dentro

Massas & DNS é uma suite de ferramentas web que roda 100% no browser — sem servidor, sem instalação, sem envio de dados — projetada para times de QA do Itaú que precisam preparar, transformar e combinar dados de teste de forma rápida e segura.

O problema que ela resolve é concreto: em um sprint típico, um analista de qualidade gasta entre 1 e 3 horas só preparando massas — copiando de planilhas, ajustando formatos, trocando URLs de ambiente manualmente, criando combinações de cenários na mão. A ferramenta elimina esse trabalho mecânico.

Como estudar este tutorial sem se perder

Se você está começando agora, não tente decorar todas as telas de uma vez. O melhor caminho é seguir esta ordem:

01
Entenda a entrada
Veja primeiro como a massa entra e como a engine interpreta o conteúdo.
02
Valide o preview
Aprenda a reconhecer cedo se o parser está correto antes de gerar qualquer resultado.
03
Gere a tabela
Depois de validar o parse, siga para filtros, abas e exportações.
04
Explore módulos
Só então avance para DNS, Diff, Cartesiano e demais páginas da suíte.
05
Repita com dado real
Volte ao início com uma massa do seu contexto e repita o fluxo completo.

Como funciona a arquitetura

Toda a lógica é executada em JavaScript puro no thread principal do browser. Não há dependências externas, chamadas de rede ou build step. O arquivo HTML é autossuficiente:

INPUT (texto / arquivo)

NORMALIZAÇÃO → array de objetos JS
  ↓ pipeline de transformação
SAÍDA → Tabela · JSON · CSV · DNS · Cartesiano · Diff
  ↓ opcional
EXPORT → clipboard · download · sessão salva

Casos de usoCenários reais do dia a dia do QA no Itaú

A ferramenta foi desenhada para cobrir os principais gargalos do fluxo de trabalho de QA. Abaixo estão os cenários mais comuns, com o contexto de cada um:

Embora o nome da página destaque massas e DNS, o uso prático vai além da simples preparação de input. A suite ajuda em diferentes frentes do ciclo de qualidade: testes funcionais, testes de integração, testes de regressão, testes exploratórios, evidências de execução, apoio à automação e sanitização de dados para ambientes não produtivos.

Quando usar
Quando você recebe massa crua, planilha, resposta de API, URLs de ambiente ou precisa comparar versões.
O que aprender aqui
Como pensar na ferramenta como fluxo: entrada, interpretação, validação, geração, refinamento e saída.
Resultado ideal
Sair do tutorial sabendo escolher engine, validar preview e exportar no formato correto sem tentativa e erro.

Cenário 1 — Preparar massa para automação

Você recebe uma planilha do squad com dados de clientes, ou extrai linhas de um banco de dados como texto. O formato é irregular. A ferramenta normaliza tudo em uma tabela estruturada pronta para carregar em um script Cypress, Karate, Postman ou Selenium.

💡
Fluxo típico: Cole os dados → escolha a engine → clique em Gerar → copie o JSON ou baixe o CSV → importe no seu framework de automação.

Cenário 2 — Trocar ambiente (DNS)

Você tem uma massa de teste com URLs de HML e precisa rodar os mesmos testes em PROD ou SIT. Sem a ferramenta, isso significa editar um arquivo JSON ou planilha à mão, coluna por coluna. Com o módulo DNS, todos os hosts são detectados e substituídos em bloco, com um clique.

ANTES: https://api.hml.itau.com.br/v1/clientes
DEPOIS: https://api.itau.com.br/v1/clientes

Cenário 3 — Combinatória de cenários (Cartesiano)

Você tem 5 perfis de usuário e 6 produtos bancários e precisa testar todas as combinações. Criar 30 linhas na mão é tedioso e sujeito a erro. O produto cartesiano gera os 30 cenários automaticamente em menos de 1 segundo.

Cenário 4 — Diff entre versões de massa

Após uma atualização de dados no banco, você precisa saber exatamente quais CPFs entraram, quais saíram e quais sofreram alteração de perfil. O módulo Diff compara as duas versões e destaca as diferenças com cores.

Cenário 5 — Geração de dados sintéticos

Para criar um ambiente de teste do zero, você precisa de 200 CPFs válidos, 200 e-mails únicos e 200 UUIDs. O Gerador de Dados produz isso em segundos, sem precisar de scripts Python ou sites externos.

Cenário 6 — Evidência e documentação

Após executar um ciclo de testes, você precisa anexar a massa usada no Jira ou em um doc de evidências. Exporte como CSV formatado ou texto de tabela e cole diretamente na sua ferramenta de ALM.

Cenário 7 — Testes de regressão

Em regressão, o maior risco é repetir execuções com massa desatualizada ou com cobertura desigual entre squads, canais e produtos. A combinação entre sessões salvas, Diff e exportação ajuda a manter um baseline estável de entrada e a rastrear alterações entre ciclos.

Cenário 8 — Testes de integração e contrato

Quando uma API depende de outra, ou quando múltiplos serviços compartilham URLs, payloads e ambientes distintos, a ferramenta ajuda a reorganizar dados por serviço, revisar hosts e montar lotes consistentes para validação de contrato, integração e fluxo ponta a ponta.

Cenário 9 — Testes exploratórios guiados

Durante exploração, é comum receber dados incompletos, copiar trechos de log, payloads quebrados, respostas parciais e tabelas improvisadas. As engines e o preview rápido ajudam a transformar esse material em algo navegável, pesquisável e exportável em poucos minutos.

Cenário 10 — Apoio à triagem de defeitos

Ao abrir um bug, o QA normalmente precisa demonstrar exatamente qual entrada foi usada, quais URLs estavam envolvidas, qual subconjunto falhou e o que mudou em relação a uma execução anterior. A suite ajuda a produzir esse pacote com menos retrabalho e mais rastreabilidade.

Passo 1 — Engine de parseComo a ferramenta lê e interpreta qualquer formato de dados

A primeira coisa a fazer ao usar a ferramenta é dizer em que formato seus dados estão. A engine de parse é o componente responsável por ler o texto cru e transformá-lo no array de objetos que alimenta todos os demais módulos.

Na prática, a engine funciona como um tradutor entre o dado original e a tabela final. Se você cola um JSON, ela converte chaves em colunas; se você cola CSV ou TSV, separa os campos; se você usa XML, YAML, SQL ou Gherkin, ela interpreta a estrutura e produz linhas normalizadas. Quando a engine correta é escolhida, todo o restante da ferramenta passa a funcionar melhor: preview, filtros, exportações, Diff, Cartesiano e substituição de DNS.

Como pensar na engine do jeito certo

Em vez de decorar nomes técnicos, faça uma pergunta simples: “de onde veio este dado?”. Se veio de Excel colado, pense em tabulação; se veio de API, pense em JSON; se veio de banco, pense em SQL; se veio de documentação BDD, pense em Gherkin. Esse raciocínio reduz muito o erro de escolha.

Passo a passo para configurar a engine

1
Abra a ferramenta no browser

Clique duas vezes em automacao-massas-dns.html ou abra pelo Chrome/Edge com Ctrl+O. Nenhuma conexão com internet é necessária.

2
Localize o seletor de engine

No topo do painel "Massa A" (e de cada painel adicional), há um dropdown com o nome da engine atual. Por padrão vem "AUTO". Clique para ver as 12 opções disponíveis.

3
Escolha a engine correta para seu formato

Selecione a engine que corresponde ao formato do seu dado. Não sabe qual? Deixe em AUTO — ele tenta todas e usa a que gerou mais colunas e linhas válidas.

4
Cole ou arraste o arquivo

Cole o texto no textarea (Ctrl+V) ou arraste um arquivo .json, .csv, .txt, .yaml, .xml ou .feature diretamente para a área. Se a origem for Excel, exporte a planilha como .csv ou copie/cole as colunas da própria planilha.

5
Verifique a pré-visualização

Abaixo do textarea aparece um mini-preview com o número de linhas e colunas detectadas. Se estiver errado, troque a engine e o preview atualiza em tempo real sem precisar clicar em Gerar.

Como validar se a engine está correta

  • O preview deve mostrar a quantidade esperada de linhas e colunas, sem concentrar todo o conteúdo em uma única coluna.
  • Os nomes de colunas devem aparecer legíveis, sem trechos quebrados por aspas, chaves ou separadores incorretos.
  • Se o dado veio de Excel copiado e colado, normalmente TSV ou AUTO funcionam melhor do que CSV manual.
  • Se o dado veio de API, arquivo de evidência ou export do Postman, normalmente JSON Array ou JSONL são as opções mais adequadas.
  • Se a saída parecer vazia, troque a engine antes de alterar o conteúdo. Na maioria dos casos, o problema está no parser escolhido e não na massa em si.
🧠
Regra prática: se o preview parece “estranho”, não avance. O tutorial inteiro fica mais fácil quando você trata o preview como checkpoint obrigatório antes de gerar a tabela.

Passo 2 — Massa de dadosComo inserir, estruturar e combinar suas massas de teste

A ferramenta aceita até 3 massas simultâneas — Massa A, Massa B e Massa C. Cada painel é independente: tem sua própria engine, textarea e botão de limpar. As massas podem ser combinadas via produto cartesiano ou comparadas via Diff.

Isso permite montar cenários completos sem precisar sair da página. Um fluxo comum é usar a Massa A como base principal de clientes ou contratos, a Massa B como complemento de produtos, perfis ou canais, e a Massa C como um terceiro eixo opcional para regras, ambientes ou parâmetros. Como cada painel é isolado, você pode testar diferentes engines e diferentes fontes sem interferir nas demais massas.

O que você vai aprender neste passo

Entrada
Como decidir o que vai em A, B e C sem misturar objetivos diferentes.
Formato
Como reconhecer exemplos corretos para JSON, CSV e TSV.
Validação
Como perceber cedo se a massa foi interpretada do jeito certo.
Combinação
Quando manter uma massa isolada e quando preparar A×B ou A×B×C.

Antes de colar qualquer conteúdo

Pergunta 1
Essa massa representa o conjunto principal que você quer analisar? Se sim, ela quase sempre deve ir para a Massa A.
Pergunta 2
Esse segundo bloco serve para comparar, enriquecer ou cruzar dados? Então normalmente ele pertence à Massa B.
Pergunta 3
Existe um terceiro eixo opcional como canal, jornada, ambiente ou produto? Use a Massa C só se isso realmente agregar.

Estratégia prática para organizar suas massas

  • Massa A: use para o conjunto principal que você deseja visualizar, filtrar, exportar e enriquecer com DNS.
  • Massa B: use para comparações no Diff ou para combinação no Cartesiano com campos complementares.
  • Massa C: use quando precisar de uma terceira dimensão, como produto, canal, ambiente, jornada ou regra adicional.
  • Se estiver em dúvida, carregue primeiro apenas a Massa A e valide o preview. Depois adicione B e C gradualmente.
  • Prefira colunas com nomes curtos e consistentes, porque isso melhora a leitura na tabela e reduz ruído nas exportações.

Entrada errada vs entrada correta

Uma das maiores causas de erro não é o parser em si, e sim a expectativa sobre o que está sendo colado. Abaixo estão dois exemplos típicos de problema e correção.

Errado

cpf,nome,perfil
111.111.111-11;João Silva;PF
222.222.222-22;Maria Santos;PJ

Certo

cpf;nome;perfil
111.111.111-11;João Silva;PF
222.222.222-22;Maria Santos;PJ

No exemplo errado, o cabeçalho usa vírgula, mas as linhas usam ponto-e-vírgula. Isso costuma gerar colunas desalinhadas ou um preview estranho. No exemplo certo, o separador é consistente em todas as linhas.

Errado

{"cpf":"111.111.111-11","nome":"João"}
{"cpf":"222.222.222-22","nome":"Maria"}

Certo

[{"cpf":"111.111.111-11","nome":"João"},
 {"cpf":"222.222.222-22","nome":"Maria"}]

Quando cada linha contém um JSON independente, isso já não é mais JSON Array, e sim um caso para JSONL ou AUTO. Se você escolher a engine errada, a massa até pode parecer válida visualmente, mas o resultado virá quebrado.

Como validar se a massa ficou boa antes de seguir

  • O preview deve mostrar mais de uma coluna quando o seu dado for tabular.
  • Os nomes das colunas devem parecer familiares e úteis, não valores de negócio misturados com cabeçalho.
  • Se tudo caiu em uma única coluna, normalmente o separador ou a engine estão errados.
  • Se surgiram colunas demais com nomes estranhos, provavelmente há linhas inconsistentes ou estruturas muito diferentes no mesmo bloco.

Passo 3 — DNS / AmbientesDetecte e substitua URLs entre ambientes com um clique

O módulo DNS resolve um dos problemas mais frequentes em QA: você tem uma massa com URLs de um ambiente e precisa rodá-la em outro. Em vez de fazer Ctrl+H num editor de texto (e torcer para não substituir nada errado), o módulo DNS detecta todos os hosts da massa, apresenta cada um individualmente, e permite trocar de ambiente por host com um clique.

O que você vai aprender neste passo

Detecção
Como a ferramenta encontra hosts automaticamente dentro das colunas.
Leitura
Como interpretar cards, badges, ocorrências e colunas afetadas.
Troca
Como mudar ambiente sem substituir texto indevidamente.
Segurança
Quais limites evitar para não perder URLs ou trocar hosts errados.

Como usar o módulo DNS

1
Cole a massa com URLs

Qualquer campo de qualquer coluna que contenha http:// ou https:// é identificado automaticamente pelo parser. Você não precisa marcar nem configurar nada.

2
Gere a tabela e vá para a aba DNS

Clique em Gerar (ou ⌘↵) e depois na aba "DNS" nos resultados. Cada host distinto encontrado na massa aparece como um card separado, com o badge do ambiente atual identificado automaticamente.

3
Escolha o ambiente destino para cada host

Para cada card de host, use o seletor de ambiente para escolher HML, PROD, DEV, SIT, UAT ou QAS. Você pode trocar hosts diferentes para ambientes diferentes — útil em integrações com múltiplos serviços.

4
Clique em "Aplicar DNS"

A massa inteira é reprocessada com os novos hosts. A aba Tabela e JSON atualizam automaticamente. Exporte normalmente — os dados já estarão com as URLs corretas.

Como interpretar a aba DNS

Host detectado
É o domínio base encontrado nas URLs. Se o mesmo host aparece em várias colunas, ele continua sendo tratado como uma única origem.
Colunas afetadas
Mostra onde aquele host apareceu. Isso ajuda a entender o impacto antes de aplicar a troca.
Ocorrências
Indica quantas linhas serão impactadas. Se o número for alto, revise o destino antes de confirmar.
Badge do ambiente
Resume o ambiente inferido pelo padrão do host. Use como pista visual rápida, não como desculpa para não revisar.

https://api.sit.itau.com.br/contratos

Sem protocolo, o módulo DNS não reconhece a string como URL completa. O resultado é simples: nenhum host aparece na aba DNS, mesmo que visualmente pareça “uma URL”.

🌐
Múltiplos hosts, múltiplos ambientes: é possível ter na mesma massa URLs de ambientes diferentes (por exemplo, um serviço de auth em HML e um serviço de pagamento em SIT). O módulo DNS trata cada host de forma independente.
🔴
URLs sem protocolo não são detectadas. api.hml.itau.com.br/v1/clientes sem https:// não será reconhecida. Sempre inclua o protocolo nas URLs da sua massa.

Passo 4 — Gerar tabelasO que acontece quando você clica em Gerar

Com a massa inserida e a engine configurada, clique em "Gerar" (botão laranja no painel central) ou use o atalho ⌘+↵. O processamento ocorre imediatamente, sem carregamento.

O que você vai aprender neste passo

Pipeline
Quais transformações acontecem entre o textarea e as abas de resultado.
Sinais
Quais indicadores mostram que a geração deu certo.
Diagnóstico
Como perceber rapidamente quando algo gerou incompleto ou errado.
Próximo passo
Como decidir se você deve filtrar, revisar DNS, comparar ou exportar.

Antes de clicar em Gerar

Checklist 1
Confirme se a engine faz sentido para o conteúdo realmente colado, não para o formato que você imagina ter recebido.
Checklist 2
Revise se a Massa A está populada. Sem ela, as abas principais ficam vazias mesmo que B e C tenham conteúdo.
Checklist 3
Se a sua massa contém URLs, tenha em mente que a aba DNS só ficará útil depois de uma geração bem-sucedida.

O que acontece internamente

1. Engine lê o texto do textarea
2. Texto é parseado → array de objetos normalizado
3. Colunas são extraídas (union de todas as keys)
4. URLs detectadas → alimentam módulo DNS
5. Cartesiano calculado se Massa B existir
6. Resultados renderizados em todas as abas simultaneamente

Como interpretar o resultado logo após gerar

O melhor hábito aqui é não sair exportando imediatamente. Primeiro, olhe para o resultado e responda três perguntas: a quantidade de linhas parece plausível? os nomes de coluna fazem sentido? a aba mais importante para o seu objetivo está coerente? Esse micro-check evita que você propague uma massa mal parseada para frente.

  • Se o número de linhas estiver muito menor do que o esperado, pode haver quebra incorreta por delimitador ou dados truncados na origem.
  • Se a tabela tiver colunas demais, com nomes longos e estranhos, revise se você colou conteúdo heterogêneo demais no mesmo bloco.
  • Se a aba DNS estiver vazia, mas você esperava URLs, volte e verifique se os dados têm http:// ou https://.
  • Se a aba Cartesiano explodir em volume, reveja se realmente precisava cruzar todas as linhas de A com todas as de B.

O que a área de resultados exibe

  • Aba Tabela: tabela interativa com header fixo, rolagem horizontal para muitas colunas, filtro em tempo real e ordenação clicando no cabeçalho.
  • Aba JSON: array formatado com indentação de 2 espaços, pronto para copiar e usar em qualquer script ou payload.
  • Aba CSV: saída separada por vírgula, compatível com Excel, Google Sheets e qualquer ferramenta que aceite CSV.
  • Aba DNS: todos os hosts únicos detectados nas URLs da massa, com controles de troca de ambiente por host.
  • Aba Cartesiano: se Massa B estiver preenchida, exibe A×B (×C se C existir) calculado automaticamente.
  • Aba Diff: comparação entre duas massas com destaque de linhas adicionadas, removidas e alteradas.

⚡
Velocidade: O processamento é síncrono em memória — massas de até 1.000 linhas são geradas em menos de 50ms. 10.000 linhas levam cerca de 300–500ms dependendo do número de colunas.
🔄
Auto-regeneração: ao trocar a engine ou editar o texto no textarea, a pré-visualização atualiza em tempo real. Mas a tabela completa de resultados só é atualizada quando você clica em Gerar novamente (ou usa o atalho).

Filtrar e ordenarNavegue e refine grandes tabelas sem esforço

Após gerar a tabela, a barra de filtro acima dos resultados permite encontrar qualquer dado instantaneamente — sem precisar exportar ou abrir outro programa.

Como filtrar

1
Clique na caixa de busca ou pressione ⌘K

A caixa de busca fica no topo da área de resultados. Você também pode focá-la com o atalho de teclado.

2
Digite o termo

A tabela filtra em tempo real à medida que você digita — sem precisar pressionar Enter. O contador de linhas atualiza automaticamente.

3
Pressione Esc para limpar

Limpa o filtro e volta a mostrar todas as linhas. Mais rápido do que selecionar o texto e deletar.

Como ordenar

  • Clique no cabeçalho de qualquer coluna para ordenar ascendente (↑).
  • Clique novamente na mesma coluna para inverter para descendente (↓).
  • Um terceiro clique remove a ordenação e volta à ordem original da massa.
  • A ordenação e o filtro funcionam juntos — você pode filtrar por "PF" e ordenar por "agência" simultaneamente.

Comportamento da busca

Termo buscadoEncontra
silva"Silva", "da Silva", "Silvana", "silverio" (case-insensitive, parcial)
0001Qualquer célula que contenha "0001" — número de agência, código de produto, etc.
pf"PF", "cpf", "perfil_pf" — busca em todas as colunas ao mesmo tempo
hml.itauCélulas com a string "hml.itau" — útil para filtrar linhas com URL de HML
🔍
A busca é global: procura o termo em todas as colunas ao mesmo tempo. Não existe busca por coluna específica — para isso, use exportação + Excel ou ordene a coluna desejada.
💡
Exportar filtrado: quando você usa o botão CSV filtrado com um filtro ativo, a exportação reflete apenas as linhas visíveis. Útil para extrair um subconjunto da massa sem editar o dado original.

Abas de resultadosSeis visões diferentes sobre os seus dados processados

A área de resultados é organizada em 6 abas, cada uma com uma finalidade específica. Você pode navegar entre elas clicando ou usando os atalhos ⌘1 a ⌘6.

Aba 1 — Tabela

A visualização mais usada. Exibe os dados como uma tabela interativa com:

  • Header fixo que permanece visível ao rolar a tabela verticalmente
  • Rolagem horizontal automática para tabelas com muitas colunas
  • Linhas com zebra-striping para facilitar a leitura
  • Clique no cabeçalho para ordenar por aquela coluna
  • Filtro global na barra de busca acima
  • Contador de linhas visíveis × total (ex: "47 / 200 linhas")

Aba 2 — JSON

Saída formatada como array JSON com indentação de 2 espaços. Ideal para:

  • Usar como corpo de requisição em testes de API (Postman, Insomnia, Karate)
  • Alimentar variáveis de ambiente em scripts Cypress ou Jest
  • Criar fixtures para testes unitários

[
  {

Aba 3 — CSV

Saída separada por vírgula com cabeçalho na primeira linha. Compatível com Excel, Google Sheets, LibreOffice e qualquer ferramenta que aceite CSV padrão RFC 4180.

Aba 4 — DNS

Lista todos os hosts únicos detectados nas URLs da massa. Para cada host você pode selecionar o ambiente destino e clicar "Aplicar DNS" para reprocessar a massa com as novas URLs. Veja a seção 6 para detalhes completos.

Exibe o produto cartesiano entre Massa A × Massa B (× Massa C, se preenchida). Só aparece populada se ao menos Massa A e Massa B estiverem preenchidas. Veja a seção 16 para detalhes.

Aba 6 — Diff

Comparação visual entre Massa A e Massa B. Cada linha é marcada com uma cor:

  • Verde: linha presente em A mas não em B (nova / adicionada)
  • Vermelho: linha presente em B mas não em A (removida)
  • Amarelo: linha presente nos dois, mas com valores diferentes (alterada)
  • Sem cor: linha idêntica nos dois (sem mudança)

Exemplo real de Diff

Suponha que a Massa A represente a versão nova de uma massa de clientes e a Massa B represente a versão anterior. O Diff ajuda a responder rapidamente o que foi incluído, removido ou alterado.

SituaçãoExemploCor esperada

Linha removidaRegistro existia em B e não existe mais em AVermelho
Linha alteradaMesmo identificador, mas campo como produto, agência ou URL mudouAmarelo

Use ⌘1 para Tabela, ⌘2 para JSON, ⌘3 para CSV, ⌘4 para DNS, ⌘5 para Cartesiano e ⌘6 para Diff. No Windows/Linux substitua ⌘ por Ctrl.

Se é só um recorte rápido

Se é para colar em documentação

Drag & DropArraste arquivos diretamente para a ferramenta

Você pode arrastar arquivos diretamente para as áreas de input de cada massa. Os seguintes tipos de arquivo são suportados:

O comportamento do drag & drop é simples: o arquivo é lido como texto, inserido no campo da massa escolhida e processado pela engine selecionada naquele painel. Por isso, o resultado final depende de duas coisas ao mesmo tempo: o conteúdo do arquivo e a engine ativa no momento do arraste.

  • .json — lido como JSON Array ou objeto
  • .csv / .tsv — lido como CSV/TSV
  • .txt — processado pela engine selecionada
  • .yaml / .yml — lido como YAML
  • .xml — lido como XML
  • .feature — lido como Gherkin

🖱️
Arraste o arquivo para o textarea da massa desejada. Uma borda colorida indica que a área está pronta para receber o arquivo.

Produto cartesianoCombine massas para gerar todos os cenários

O produto cartesiano combina cada linha da Massa A com cada linha da Massa B (e opcionalmente da Massa C), gerando A×B (×C) combinações.

Exemplo: Massa A tem 3 usuários × Massa B tem 4 produtos = 12 cenários de teste gerados automaticamente.

Exemplo real de produto cartesiano

Imagine que você precisa validar combinações entre perfis de cliente e tipos de produto. Em vez de montar tudo manualmente, você separa os conjuntos e deixa a ferramenta gerar as combinações.

Para ampliar a cobertura funcional, a suíte agora inclui a página Casos de Teste, com cenários sugeridos para parsing, Diff, Cartesiano, DNS e exportação, além da página Exemplos Práticos para fluxos guiados.

Massas de entrada
// Massa A
perfil
PF
PJ

// Massa B
produto
Conta Corrente
Cartão
Empréstimo

Resultado esperado: 2 perfis × 3 produtos = 6 cenários. Cada linha da saída representa uma combinação válida para automação, evidência ou planejamento de testes.

1
Preencha Massa A e Massa B

Insira dados independentes em cada painel. Eles não precisam ter as mesmas colunas.

2
Acesse a aba "Cartesiano"

Nos resultados, selecione a aba "Cartesiano". O produto é calculado automaticamente.

3
Revise e exporte

A tabela mostra todas as combinações. Exporte como CSV ou JSON normalmente.

⚠️
Atenção: O número de combinações cresce exponencialmente. 100 × 100 × 100 = 1.000.000 linhas. A ferramenta tem limite de 50.000 combinações para manter a performance.

Como salvar e restaurar uma sessão

1
Clique em "Salvar sessão"

2
O estado atual é capturado

3
Restaure quando precisar

Boas práticasDicas para uso eficiente e seguro

  • Nunca use dados de produção reais — crie massas com dados sintéticos ou anonimizados para testes.
  • Valide o engine antes de processar: confira se a pré-visualização corresponde ao esperado antes de gerar a tabela completa.
  • Nomeie suas sessões: use nomes descritivos (ex: "Sprint 44 — Regressão Pagamentos") para encontrá-las depois.
  • Use o produto cartesiano com moderação: prefira massas compactas (menos de 50 itens cada) para evitar tabelas enormes difíceis de gerenciar.
  • Exporte antes de fechar: embora o auto-save esteja ativo, é uma boa prática baixar um CSV/JSON após cada sessão importante.
  • Ambiente correto antes de copiar URLs: sempre verifique o badge de ambiente na aba DNS antes de copiar URLs para scripts de teste.

Boas práticas por área de QA

Funcional
Monte massas pequenas, legíveis e com campos de negócio claros para facilitar leitura, execução manual e evidência.
Automação
Prefira JSON para consumo por scripts e use sessões salvas para manter uma base reprodutível entre execuções.
Integração
Revise DNS por host antes de disparar testes que envolvem múltiplos serviços, gateways ou webhooks.
Regressão
Use Diff entre ciclos para entender o que mudou na massa antes de concluir que houve defeito funcional.
Exploratório
Aproveite AUTO, filtros e exportação rápida para organizar achados sem interromper o raciocínio da sessão.
Evidência
Exporte apenas o recorte necessário, com contagem conferida, para não anexar informação demais ou de menos.

HOM

Ambiente HOMComo preparar massas para homologação e usar a ferramenta dedicada

HOM (Homologação) é o ambiente de pré-produção onde as funcionalidades passam por validação final antes de ir para produção. É o destino padrão para testes de aceitação (UAT) no Itaú. Preparar a massa corretamente para HOM evita falsos negativos causados por hosts de ambiente errado.

🏷️
Regra de ouro: Nunca use CPFs ou contas reais em HOM. Use dados sintéticos gerados pela suite ou datasets mascarados aprovados pelo time de segurança.

Padrões de host HOM

As URLs de HOM no Itaú seguem convenções que as distinguem dos demais ambientes:

-homologapi-homolog.itau.com.brapi-uat.itau.com.br

Convertendo massa para HOM

A suite oferece duas formas de converter massas para o ambiente HOM:

Ferramenta HOM
Cole qualquer massa com URLs, selecione o sufixo HOM e clique em Converter. Ideal para conversões rápidas de uma única massa.
Módulo DNS (ferramenta principal)
Use o módulo DNS da ferramenta principal quando precisar de múltiplos ambientes simultâneos, produto cartesiano ou substituição mais granular.

Fluxo resumido para HOM

CSV, JSON ou lista de URLs de DEV ou SIT que será a base dos seus testes.

Valide um subconjunto pequeno antes de rodar a suite completa para confirmar que o ambiente está respondendo.
